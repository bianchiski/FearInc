# owasp

## Simple version

Think of this topic as a tool that helps you organize a messy problem. You do not need to memorize everything before practicing. First, understand the picture and the reason the tool is useful.

## How to picture it

Start with a tiny example. Draw the values, follow one operation by hand, and say out loud what changed. In an interview, explaining the picture is often more valuable than rushing to code.

## Interview version

Before coding, identify the input, the output, the operation you need to make fast, and the edge cases. Then state the expected time and extra-space cost in plain language. The exercise attached to this topic gives you a small, focused way to practice.

## Common traps

- Starting to code before checking an empty or very small input.
- Choosing a data structure because it is familiar instead of because it fits the operation.
- Saying a solution is fast without explaining what happens as the input grows.

### Tiny glossary

- **Input:** the information your code receives.
- **Output:** the answer your code should produce.
- **Edge case:** a small or unusual input that can reveal a bug.
- **Complexity:** how time or memory changes as the input grows.

Read this only as much as you need, then try the exercise.


## New learner checkpoint

Before solving, say the input, output, and one edge case in your own words. If a term feels unfamiliar, use the glossary and then return to the exercise.
